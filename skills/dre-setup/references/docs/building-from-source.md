# Building from source

Use a source build to develop DRE or test a change before a release. Requires a recent stable
Rust toolchain, and Go for the Databricks, BigQuery and Snowflake packages.

```bash
cargo build --release
./target/release/dre --help
```

The first-party plugin packages are built from the same workspace
(`target/release/dre-plugin-*`), except the Go packages (`databricks`, `bigquery`, `snowflake`)
in `go/`:

```bash
for p in databricks bigquery snowflake; do
  (cd "go/$p" && go build -o "../../target/release/dre-plugin-$p" .)
done
```

Put them in a project's `dre_deps/plugins/` (or point `DRE_PLUGINS_DIR` at them) to use them
without a registry.

For a full local trial, build only the needed packages and use the
[tutorial project](https://github.com/get-dre/dre/blob/master/examples/tutorial/):

```bash
cargo build --release -p dre-cli -p dre-plugin-duckdb -p dre-plugin-csv
export DRE_PLUGINS_DIR="$PWD/target/release"
./target/release/dre validate --project-dir examples/tutorial --no-auto-install
./target/release/dre run --project-dir examples/tutorial --no-auto-install --preview 5
```

If `CARGO_TARGET_DIR` is set, substitute that directory for `target` in every command. Avoid
copying a build for another architecture; a plugin must run on the same machine as `dre`.
`plugin-not-installed` means the binary name or plugins directory does not match discovery;
`plugin-install-failed` describes a download problem, not a Rust compilation failure.
The [protocol](protocol.md#naming-and-location) specifies discovery layouts,
the [CLI reference](cli-reference.md) lists flags, and the
[glossary](glossary.md#plugin-package) defines packages.
